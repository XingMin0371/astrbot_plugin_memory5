# 鱼鱼日记 · 如鱼所书（memory5）

群聊一多，模型就容易「失忆」：要么把整段聊天塞进上下文，Token 消耗得很快；要么记不住谁是谁，刚说过的话转头就忘。

这个插件想解决的就是这件事——把聊天整理成分层日记，用得上的时候再拿出来。省 Token，但不丢记忆。

> 插件内部名：`memory5`，目录、配置、数据路径一直不变。

## 它怎么想的

不是把聊天记录一股脑堆进去，而是先整理：

1. 分层。长期、重要、提醒、普通、低密度，各管各的保留期和注入额度。
2. 归档。到了时间点，把原始消息交给模型整理成条目，跨标签去重，够格的才进长期。
3. 按需要注入。每轮只带相关的那几条，超预算就按优先级裁掉。
4. 想翻细节，去面板里翻，而不是一直占着上下文。

说白了，它不是在「记住更多」，而是在「记住该记的」。

## 用起来大概是这样

- 上下文短了。不再每轮都背着几百条聊天记录，长会话也不会越聊越贵。
- 记忆稳了。长期的事实、称呼、关系一直在；闲聊该退场就退场。
- 想改能改。面板里按群、按 QQ、按日期翻，写错了能改，删了能恢复。
- 心里有底。日记落盘是密文，密钥只在本机。

## 分层

| 层 | 放什么 | 干什么用 |
|---|---|---|
| 长期 | 稳定的事实、关系、称呼 | 每轮优先注入 |
| 重要 | 有影响、但不必长期留着的事 | 按预算注入 |
| 提醒 | 带到期时间的事 | 到点发送，临期注入 |
| 普通 / 低密度 | 日常闲聊 | 随机抽一点，保留期短 |

分层看三个维度：稳定度、影响力、信息量。阈值都在设置里，觉得不合适可以自己调。

## 归档流程

```
原始消息（按天存 jsonl）
  → 到点触发（默认 04:05 / 16:05）
  → 模型整理成条目
  → 跨标签去重
  → 够格的升级进长期
  → 重排序号、刷新索引
```

## 注入

按预算拼：长期 → 共享身份/称呼/关系 → 重要 → 随机普通。超预算就按优先级裁。提醒只在触发点前后那段时间注入。

关键不是带得多，而是需要的那部分刚好在。

## 加密

三档：

- 高性能：AES-256-GCM
- 平衡：AES-256-GCM + HKDF-SHA256 子密钥（推荐）
- 安全：再加一层 HMAC-SHA256

密钥第一次启动自动生成，支持按半天/一天/一周/一月/一年轮换。密钥真丢了，可以在设置里走三级确认重置——旧数据会挪到 `memory5-old-时间戳`，新钥解不开，但至少不会当场删掉。

## 面板

- 按范围（群 / 私聊）、按日期（日历，也能选「全部」）看
- 长期 / 重要 / 提醒 / 普通 / 低密度 / 别名 / 回收站 / 定时任务
- 编辑、删除（进回收站 7 天）、恢复、彻底删除
- 批量删除、批量调等级，按日期加序号定位
- 导出 JSON / Markdown，带导出历史
- 运行状态：版本、会话、加密、缓存、条目数、备份校验


### 管理员授权

设置里有「管理员账号类型」：

- **QQ号**：填 QQ，插件按 QQ 私聊验证
- **其他平台账号**：填 Telegram/Discord 等平台的用户 ID，按平台账号私聊验证

切换类型会清空已授权列表，需要重新回复 `「验证码 + 已确认授权」`。


管理员 QQ 填进设置后不会立刻生效：插件会私聊对方，要求回复 `「验证码 + 已确认授权」`，24 小时内没确认不生效。确认后会写入一条长期记忆「该 QQ 是鱼鱼的管理员」；从设置删掉时发一条移除通知，不需要确认。

### 归档压缩

- 归档前默认过滤低密度和低关联内容：过短、复读、词汇重复、重复归档提示、拍一拍、表情包分享和与前后文无共同词的碎片会被丢弃；中文按字、英文按词、数字按段计数，人物、提问、时间、约定和重要事件关键词优先保留，可在设置「归档」中关闭或调整阈值

### 心跳与自检

- 每 90 秒写一次心跳，事件循环延迟超过 8 秒写警告日志
- 面板「运行状态」显示最后心跳和延迟
- 点「自检」检查数据目录、密钥、加解密、数据库、模型、磁盘、心跳，日志写到插件数据目录，超过 15 天自动删

## 提醒和定时任务

- 提醒：提前量、提醒次数、补发宽限、过期怎么回落，都能调
- 重复：每天 / 每周 / 工作日
- 定时任务：一次性 / 每天 / 每周，能发图片、语音、视频

## 功能

- 分层日记，自动归档
- 按需注入，Token 预算可控
- 提醒到点发送，临期注入
- 定时任务、富媒体
- 面板查看 / 编辑 / 删除 / 恢复
- 别名管理（QQ、昵称、置信度）
- 导入导出、导出历史
- 三档加密、密钥轮换、备份校验
- 敏感词脱敏，内置词表，也能自己加
- 多会话、多群、私聊

## 适合什么样的用法

- 群多、消息量大，Token 花费涨得比较明显
- 想让 AI 记住人和事，又不想一直背着整段聊天
- 在意隐私，希望日记落盘是密文
- 记忆写错了想自己改，而不是模型记成什么就是什么

## 不太适合

- 只想无脑全文记忆、不在乎 Token 的
- 不想配模型，装完就想完全不用管的——归档质量依赖模型

## 从旧版本升级

第一次启动会自动把旧的 `<数据目录>/memory5/` 和 `<数据目录>/.memory5.key`（旧版，已迁移） 迁移到 `plugin_data/astrbot_plugin_memory5/`（密钥在 `keys/memory5.key`），旧目录会清空，不需要手动搬。

## 兼容性

不依赖 SnowLuma。任何 AstrBot 支持的 OneBot v11 / aiocqhttp 平台都能用：

- 插件按收到的消息自动记录真实会话标识，定时提醒和定时任务会回到原会话
- 没有历史记录时，可用环境变量 `MEMORY5_PLATFORM` 指定平台名（默认 `aiocqhttp`）
- 换平台、换网关不需要改代码

## 安装

1. 把 `astrbot_plugin_memory5` 放到 AstrBot 数据目录的 `plugins/` 下
2. 重启 AstrBot
3. 第一次启动会自动生成密钥，打开插件面板就能用

详细步骤见 [DEPLOY.md](DEPLOY.md)。

## 配置要点

- 记录的会话：`group:群号` 或 `private:QQ号`，不填就不归档
- 管理员 QQ：能看全部日记，能用重要级命令
- 机器人 QQ：用来认出自己说的话
- 注入预算：默认 3600 字符，按需调
- 加密强度：平衡就够用，切换会自动重加密

## 命令

```
/记忆查看 [日期] [QQ] [普通级|提醒级|重要级|低密度级] [条数]
```

长期记忆只在面板看。

## 数据放在哪

```
<数据目录>/plugin_data/astrbot_plugin_memory5/memory5/
├─ group_xxx/ private_xxx/
│  ├─ core.md important.jsonl remind.jsonl
│  ├─ daily/*.jsonl raw/*.jsonl
│  ├─ aliases.json index.json
├─ tasks.json
├─ trash/ media/ backup_policy.json
└─ export_history.json
```

密钥在 `<数据目录>/plugin_data/astrbot_plugin_memory5/keys/memory5.key`。

## 隐私

- 没配置的会话不采集
- 黑名单里的 QQ 不记录
- 日记加密落盘
- 面板走 AstrBot 登录态
- 备份可校验、可解密
- 会话、日期、媒体路径都有格式校验，防止路径穿越
- 面板字段做 HTML 转义，避免存储型 XSS
- 上传只接受常见图片扩展名

## 说点实话

- 归档靠模型，模型能力不够时，条目质量会下降，偶尔需要手动改
- 加密之后没法拿文本编辑器直接看
- 会话特别多时，第一次读会慢一点，后面有缓存

- 只处理群聊/私聊，其他消息类型不归档
- 非 QQ 平台没有 `platform_message_history` 可补，归档只靠实时采集
- 模型必须能输出结构化条目，完全不肯输出 JSON 的没法归档
- macOS 未实测
